# 1.11 [rule] Deploy, a command with a live check (long form)

> **Long form.** The binding text is the short form in `law/engineering-law.md`, which the
> user-global `CLAUDE.md` loads into every session. This file keeps the reasons and the full
> wording the short form compresses; read it when a rule needs its reasoning. If the two ever
> differ, the short form wins and this file is the defect.

**Deploy is a command, not a step of the loop.** A task ends at its commit. Nothing leaves the
repository until the user says "deploy"; a push or merge that deploys, a flag flip and a config
change on a live environment all count as a deploy and wait for that word.

**On "deploy", three things, in order, each with its output pasted:**

1. **Run the checks** (the map's lint, typecheck, test and `ui_check` commands) on the exact commit
   being shipped, and stop on a red one: a check that was already red before the change is a
   follow-up (1.9), and it still stops the deploy.
2. **Deploy**, the way the project's map or its deploy notes say.
3. **Verify live** before calling it done or flipping anything else: real requests against the
   deployed version, with clean logs, pasted. A deploy nobody verified is a deploy nobody can
   defend, and 1.5 governs the claim that it worked.

Since 10.0.0 this is the whole rule, at the user's word ("Deploy is not part of the loop. When I
say 'deploy': run the checks, deploy, run the live check. A command, not a mode."). The six proofs
that used to come before a deploy (a boot of the artifact on a production-like copy with a smoke
test, new behaviour behind switches that default off, migrations applied and rolled back on that
copy, the regression check with the switch off, no other deploy in flight, the rollback named) are
no longer required; a project that wants any of them writes it into its own map, and the law's
floor rule then binds it.
