# 1.1 [rule] Hard caps, the zero-tolerance bans, one thing per file (long form)

> **Long form.** The binding text is the short form in `law/engineering-code.md`, which
> the oneloop code-rules hook hands to the session with the first code file it reads or edits. This file keeps the reasons and the full
> wording the short form compresses; read it when a rule needs its reasoning. If the two ever
> differ, the short form wins and this file is the defect.

**Caps.**

- **≤ 3 parameters.** Group into a named interface or DTO if more.
- **≤ 3 levels of nesting.** Guard clauses and early returns over deep nesting.

**Bans, zero tolerance, in production code.**

- **0 lint, type or coverage suppressions**: no `biome-ignore`, `eslint-disable`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, no coverage-ignore marker (`istanbul ignore`, `c8 ignore`, `v8 ignore`), and no equivalent in any other language or tool. Sole exception: `@ts-expect-error` in a test file over deliberately invalid input, with a comment saying WHY; test files are exempt from the other bans in this list, never from this one. These tokens stay literal here because they are among the strings the scouts grep for; 9.5 carries the full list and 16.7 the per-language analogs.
- **0 non-null `!` assertions.**
- **0 empty catches.** `catch (e) {}` and every equivalent is banned unconditionally: a catch holding only a comment, a `.catch(() => {})` on a promise, an `except: pass`, an error discarded into `_`.
- **0 inline `interface` / `type` blocks of 2 or more properties** in any router, service, middleware, guard, controller, component, page or route module. Extract to a `*.types` file in the feature's `types/` folder.
- **0 bare `Error` throws** in domain code, `Error` or any other built-in error class (`TypeError`, `RangeError`, a JVM or .NET `RuntimeException`), with or without `new`, and none of its cousins: no thrown string, number or object literal, no `Promise.reject(new Error(...))`. Throw a domain-specific exception subclass.
- **0 focused or skipped tests committed.** No `.only`, `fit` or `fdescribe`; no `.skip`, `xit`, `xdescribe`, `test.todo` or a language equivalent without a ticket or an owner on the same line. A focused test silently drops the rest of the suite. This ban is written for test files, which the other bans exempt.
- **0 debug artifacts.** No `debugger` statement in production code; no `console.*` call in domain code, which logs through the project's logger.

On Claude Code, the edit guard (the law, Guards) points at an edit that adds one of the tokens the law scout (9.5) can judge without a lexer, and the same for the names, the file kinds, the caps a grep can count and a new top-level folder the map does not list (12.0.0, at the user's word: every law enforced, the technology's need the one exception; 14.0.0, at their word again: nothing blocks an edit, the hook points and Claude fixes). The pointer names each rule, its line and its fix; the line is fixed in the next edit, never routed around through the shell, and a technical exception is written on that line as `law-exception: <what the technology needs>` and listed in the final reply. What a grep cannot see is yours to judge when you read the diff at the loop's Check step.

**File separation, one thing per file.**

- **One component per file**, public or private. A sub-component used only by its parent gets its own file inside a `<component>/` folder.
- **One class per file.** Its private helpers stay with it. This is one class per file, not one function per file.
- **A dedicated file per concern**: types → `*.types`, constants → `*.constants`, config → `*.config`, schemas → `*.schema`, style tokens and class-name maps → `*.styles`. Implementation files import these; they never declare them. Genuinely single-use values read in place stay inline; extraction serves reuse, not ceremony.
- **One folder skeleton per repository.** Every module follows the same documented layout. "Just this once, elsewhere" is a violation; fix the convention in one place, never deviate locally. Section 2.3 is read before any file is created; where the repository has no convention for that kind of file, it sends you to 2.2, the placement contract.
- **A technical exception must cite the concrete compiler or linter error it prevents**, on the line, as `law-exception: <what the technology needs>`: the comment the edit guard's pointer names and the law scout lists (`note.law-exception`), so every exception in a codebase can be seen. An undocumented inline exception is a finding.

**Always-on principles.**

- **Reusable, generic, shareable, the prime directive.** Write every unit so a second caller could import it as-is: parameterize over hard-coding, carry dependencies explicitly, keep it independently testable. Extract on the SECOND use, never speculatively; a generic contract (below) is the one exception.
- **DRY, with the search shown.** Before writing a function, type, constant, schema or component, search the repo for one that already does it, and reuse or extend it. Every new symbol a stage adds carries the search that found no equivalent, pasted (1.5); a new symbol whose equivalent existed is a finding (`style.reuse`, `style.dry`). The same 3+ lines twice → extract.
- **Named types.** Any object shape with 2+ properties is a named `interface` or `type`.
- **Single responsibility.** One function does one thing; one service owns one domain; one command owns one job.
- **Explicit over clever.** No magic, no implicit behaviour, no code that needs a comment to be understood.
- **Edge cases.** Handle null, undefined, empty, concurrent and partial-failure paths. Do not hope.
- **Leave nothing behind.** A change deletes what it orphans: the callee whose last caller it removed, and the import, type, constant, schema, fixture, flag, config key, env var, translation, test and doc line that served only what it replaced. Git is the history. Every task sweeps its own leftovers before it commits (the loop's one read of `git diff`); dead code that was already sitting in a file the task touched is a follow-up with its `file:line`, never a hunk of this diff (1.9).
- **Comments.** Default to none. Write one only when the WHY is non-obvious.

**Generic contracts (DRY, SOLID).** The one abstraction built before its second use, because that second use is certain: every entity gets the same create, read, update, delete and list, every endpoint validates, pages and maps its errors the same way, and every external service needs the same client plumbing. Waiting for the second module only buys a copy to unpick later.

- **A closed list.** CRUD over an entity, through its repository, service and handler (the controller, route or resolver); validation; pagination (a bound and a cursor, 1.3); error mapping (domain errors to the transport's responses); an API client (auth, timeouts, retries, error translation). Anything else waits for its second use, and a one-off rule dressed as a contract is speculation (`solid.yagni`).
- **The framework's own first.** Where the stack ships a generic contract (a generic repository, a resource controller, a model view set), modules use it; a second generic layer wrapped around it is indirection (`style.object.middle-man`). The project writes one only where the stack has none, and a module searches for the project's before writing its own (the DRY search above).
- **In the language's own form**, generic over the entity and its id, never over an untyped value: an interface with a generic implementation (TypeScript, Java, Kotlin, C#), a trait with default methods (Rust), a protocol with a default extension (Swift), a generic interface and a struct the module embeds (Go), a `Protocol` or a generic base class (Python), a mixin module (Ruby). Named by its role (`CrudRepository`, `ReadRepository`), as the names rule asks.
- **Depend on it, extend it, never edit it for one module (DIP, OCP).** A service takes the contract through its constructor and the composition root wires the implementation; a module adds behaviour by extending or composing, and the contract changes only when every module needs the change.
- **Split by role (ISP, LSP).** Reading and writing are separate contracts, the full CRUD one the pair of them; a read-only module takes only the reader, so no override throws "not supported" (`style.class.refused-bequest`).
- **Write only what differs.** A module with nothing special is the generic implementation given its entity; one with extra queries extends it one level or wraps it; the hierarchy limit of the clean-code floor (line 9 below) still holds.
- A module that already exists outside its contract is a follow-up (1.9), never rewritten in another task's diff; the codebase audit finds such modules (16.6, `style.dry`).

**Idiom.** Code reads as the language's own docs and its community write it, because that is the code every reader, tool and library already expects, and the language's own constructs are usually the ones its runtime and compiler make fastest.

- **The repository's conventions first**, then the language's: a convention the codebase already set wins (the law, precedence), and matching the surrounding style (1.6) still holds.
- **The style guide and the formatter** the community settled on, or the project's own config of them; the formatter's output is never hand-edited against.
- **Built-ins and the standard library first.** The language's own collections, iteration, strings, dates, paths, concurrency and I/O come before a hand-rolled helper or a new dependency.
- **The newest stable features and APIs the pin allows.** Read the pinned version before writing: the manifest's engines or toolchain field, a version file (`.nvmrc`, `.python-version`, `.tool-versions`), the compiler target, the map. Use what that version offers; a feature newer than the pin breaks the build, and a preview or experimental one is not stable.
- **Verified, not remembered (1.5).** An API not already used in the repository, or newer than you know well, is checked against its current docs this session; `unverified` is never built on.
- **Never a deprecated API in new code.** Deprecated calls already around it are follow-ups (1.9), neither copied nor rewritten in this diff.

**The clean-code floor, ten lines distilled from the clean-code catalog (section 3.4).** Judged, not grepped, when you read the diff; a finding cites the catalog row.

1. **A function does or answers, never both.** A query has no side effect; a command returns nothing it did not change.
2. **No flag parameters.** A boolean that switches behaviour is two functions, or a named option.
3. **Inputs are never mutated.** Return a new value; mark shared data read-only; mutate only what you own.
4. **Fail fast at the boundary.** Validate on entry, throw at the first bad state, never carry a bad value inward.
5. **One level of abstraction per function.** Orchestration and byte-pushing never share a body.
6. **Talk to what you hold.** No `a.b().c().d()` into another object's internals; ask the nearest object.
7. **Every error keeps its cause and its context.** Wrap and rethrow with `cause`; never log-and-continue where the caller cannot proceed.
8. **Every promise is awaited, returned or handled.** No floating promise; no sleep standing in for a signal.
9. **Composition before inheritance.** No hierarchy deeper than two, none built to share code outside a generic contract's implementation (above).
10. **A closed set is a type, not a string.** Enum or union for statuses, kinds and ids; a domain value is never a bare primitive.

**Refuse on sight.** "Add error handling later"; a `TODO` with no owner; a fallback for a hypothetical future requirement; a backwards-compat shim for code that is never deployed; a half-finished implementation; re-exporting types "for convenience"; a `// removed: <X>` comment for deleted code; a block of commented-out code; a symbol your change left with zero references.
