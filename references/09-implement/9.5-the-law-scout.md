# 9.5 [scout] The law scout

## Law-scout (deterministic engineering-law scan)

A predictable scan that surfaces **engineering-law violations** in code, keyed to the stable `rule_id`s in the audit rule catalog (16.4). Two things run it: the edit guard (the law, Guards), over the text of every edit as it is written, and the codebase audit (16.3), over a whole tree. Nothing runs it as a step of the loop: the loop's Check step reads the diff once, and this page is where the patterns and the ids that read cites live.

It finds `ban.*` / `cap.*` / `sec.*` / `clean.*` / `test.*` / `name.*` / `file.*` rule breaks and `style.flag-parameter`, and lists the lines that state an approved exception (`note.law-exception`). Performance waste (3.1), security beyond secrets (3.2), and the naming and placement rules that need a reader (a verb-first name, a nesting depth, the repository's own layout, an abstraction level) are judged by reading, never grepped.

### WHAT

- **Deterministic finder.** Same files in, same findings out. The mechanical tier is the project's own scanner or linter where it has one for a rule, and otherwise the regexes below run as greps. Every finding carries `rule_id, file, line, evidence, proposed fix, status`, and every line the block prints starts with the `rule_id` that fired (`ban.suppression src/x.ts:1:…`), so a finding's rule id is read off the output, never inferred; a line two rows hit appears twice, once per rule.
- **A scan, not a judgment.** The guard's run reads one edit and points at the breaks it adds, which Claude fixes in its next edit; the audit's run (16.3) enters that route's report-and-approve loop. Neither adds a review pass to the loop.
- **Scoped to what was written.** The guard looks only at the text an edit adds, so a legacy repo does not drown a new feature in inherited findings; whole-codebase sweeps are the codebase audit's (16.3) job, on the user's command.
- **Enforced at write time, on Claude Code.** The edit guard runs this block over the text an `Edit`, `Write`, `MultiEdit` or `NotebookEdit` call would write, and points at the edit when any row gains a line (12.0.0, at the user's word: "these laws are my own coding style, i want to enforce every single law … claude models can't ignore them unless the target technology will break if it used them"; 14.0.0, at their word again: "nothing should block file edits … auto-pilot mode with self-control", "hooks shall point and claude fixes raised problems"). Nothing blocks the edit; the pointer names every rule the edit adds, its line and its fix, and Claude fixes the line in its next edit, never routes around it through the shell. The one thing that stays is a technical exception, recorded on that line as a comment `law-exception: <what the technology needs>`, which the `note.law-exception` row lists for the audit and the reader; a line that already states its exception is still pointed at, with the exception quoted, so nothing passes on its own say-so. What was already in the file is never pointed at: the block runs over the text being replaced too, and only a count that grows counts (a new file has nothing to compare against, so all of it counts). Test files keep the suppression, test-hygiene and secret rows, and a test that plants a banned token as fixture text writes it in two pieces, since the guard cannot tell a fixture from a directive. This block is the one source of the patterns, so an edit here changes the guard too; the guard adds one rule of its own, `folder.unlisted`, a `Write` that creates a file under a top-level folder the map's Key directories do not list, because only the guard sees the map. Every file written by any other means is caught when the Check step reads the diff, or by the audit.
- **Candidates, not verdicts, for the syntactic rules.** `ban.bare-error`, `ban.inline-type` and the `console.*` half of `clean.debug-artifact` are matched exactly but need a one-step scope check (is the throw in domain code, does the type have 2+ props, is the file domain code). The `name.*`, `file.*`, `cap.*` and `style.flag-parameter` rows read declarations, paths and signatures without a parser, so a name a framework fixes, a boolean a callback receives, or a class an injector fills is weighed by Claude when the pointer names it, and a `law-exception:` on the line records why when the technology needs it. Everything else is `confidence: exact`, the match IS the violation.
- **A rule with a domain is scanned in its domain.** The inline-type ban's mechanical tier is the five scoped role files (16.5), the focused and skipped-test rules exist only in test files (the code rules' definition of a test file, every language's convention), the `console.*` rule only in domain roles, the non-null `!` row only in the files whose language reads a postfix `!` as non-null (16.5), and the case rows only in the languages whose convention is the law's: camelCase declarations in the ECMAScript family, Kotlin, Swift, Dart and Java, snake_case in Python, Ruby, Rust and Elixir, PascalCase file names where the language demands them (Java, Kotlin, C#, Swift, Dart, PHP) and snake_case ones where it does (Python, Ruby, Rust, Go); never Go's symbol case, which is visibility, and never C#'s `I` prefix, which is that language's own. Scanning those rules there is their scope, not a carve-out: every path in the list is still read by every other scan.

### WHEN

| Run point | Scope | What happens with findings |
|---|---|---|
| **Every edit** (the edit guard, the law's Guards) | The text the edit adds, never what was already in the file | One pointer naming every rule that gained a line, each with its line and its fix; nothing blocks the edit, the line is fixed in the next edit, never routed around; a technical exception is written on the line as `law-exception: <what the technology needs>`. |
| **The codebase audit** (16.3, on the user's command) | The whole tree, the carve-outs (16.5) applied to the finding, never to the scan | Every row goes into the audit's table (16.8) with its `rule_id`; the judgment checks (16.6) set the final severity; fixes are proposed and confirmed one finding at a time. |

Nothing runs it as a step of the loop. The Check step's one read of `git diff` catches what
the guard leaves alone, and a finding that was already in a touched file is a side find (1.9),
never fixed in this diff.

### HOW

```bash
# 1. Build the path list. Run by hand it is the change against the base. The code-rules hook
#    and the codebase audit each swap the `git diff` line below whole for their own list (the
#    text of one edit; a whole tree) and run the rest unchanged.
git diff -z --name-only "<base>..HEAD" -- . > "$SCOUT_PATHS"
#    A list with paths and no NUL was built without -z: refuse it, or every scan below
#    reads clean over nothing.
[ -s "$SCOUT_PATHS" ] && [ "$(tr -cd '\0' < "$SCOUT_PATHS" | wc -c | tr -d ' ')" -eq 0 ] && { echo "SCOUT_PATHS is not NUL-separated"; exit 1; }

# 2. Run the construct bans over ONLY those paths. Every hit is a CANDIDATE, not a verdict:
#    grep has no lexer, so open the line and confirm the token is code before you stage it.
#    `-e` carries the pattern, so a pattern that starts with `-` is never read as an option.
#    `-r` (accepted by BSD and GNU xargs) keeps an empty scope from running a tool over stdin.
scan()  { xargs -0 -r grep -nE  -e "$1" -- /dev/null < "$SCOUT_PATHS"; }
scani() { xargs -0 -r grep -niE -e "$1" -- /dev/null < "$SCOUT_PATHS"; }
#    tag <rule_id>: every line printed below starts with the rule that fired, the staging
#    table's first column, so it is copied, never inferred.
tag() { sed "s#^#$1 #"; }
#    in_paths <glob>...: the subset of the list that matches a glob, still NUL-separated, for
#    the rules whose domain is a role file, a test file or a language (16.5). The path stays
#    in the list for every other scan; only this rule looks at its own domain. A glob with a
#    slash matches the whole path (`*/tests/*`); a glob without one matches the file name
#    alone (`*.test.*`, `test_*`), so a directory named like a test file does not make every
#    file under it one. A test file is what the law's Definitions names, in every language.
in_paths() { while IFS= read -r -d '' p; do n=${p##*/}; for g; do case "$g" in */*) t=$p ;; *) t=$n ;; esac; case "$t" in $g) printf '%s\0' "$p"; break ;; esac; done; done < "$SCOUT_PATHS"; }
in_scoped() { in_paths '*.service.*' '*.controller.*' '*.routes.*' '*.middleware.*' '*.guard.*' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_domain() { in_paths '*.service.*' '*.use-case.*' '*.usecase.*' '*.repository.*' '*.validator.*' '*.job.*' '*.worker.*' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_tests()  { in_paths '*.test.*' '*.spec.*' '*_test.*' '*_spec.*' 'test_*' '*/tests/*' 'tests/*' '*/test/*' 'test/*' '*/spec/*' 'spec/*' '*/__tests__/*' '__tests__/*' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_nonnull() { in_paths '*.ts' '*.tsx' '*.mts' '*.cts' '*.js' '*.jsx' '*.mjs' '*.cjs' '*.vue' '*.svelte' '*.swift' '*.kt' '*.kts' '*.cs' '*.dart' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
#    An owner or a ticket right after a debt marker, `(name)`, `@name`, `[name]`, `#123` or
#    `ABC-123`, makes it owned (1.1: a TODO with no owner). The same marks anywhere after a
#    skip token make a skipped test owned. A marker followed by a dot is a file name
#    (`TODO.md`, the checklist), not debt.
OWNED_MARK='\([^)]*\)|@[a-z][[:alnum:]_.-]*|\[[^]]*\]|#[0-9]+|[A-Z][A-Z0-9]+-[0-9]+'
OWNED_DEBT="(TODO|FIXME|HACK|XXX):?[[:space:]]*($OWNED_MARK)"
OWNED_SKIP="(skip|todo|Skip|SkipNow|Ignore|Disabled|ignore|xit|xdescribe|xtest|xcontext|markTestSkipped)[^[:alnum:]_].*(#[0-9]+|[A-Z][A-Z0-9]+-[0-9]+|(^|[^[:alnum:]_.])@[a-z][[:alnum:]_.-]*)"

#    ban.suppression: the ECMAScript-family tokens 1.1 names, their siblings, and the
#    coverage-ignore markers; then the analogs from 16.7, which cost nothing on a tree
#    that has none of them and catch a mixed repo without a translation step.
scan  'biome-ignore|eslint-disable|@ts-ignore|@ts-expect-error|@ts-nocheck|oxlint-disable|deno-lint-ignore|tslint:disable|stylelint-disable|noinspection|NOSONAR|\$Flow(FixMe|Ignore|ExpectedError|Issue)|(istanbul|c8|v8|node:coverage)[[:space:]]+ignore' | tag ban.suppression
scan  '#[[:space:]]*(noqa|type:[[:space:]]*ignore|pyright:[[:space:]]*ignore|pylint:[[:space:]]*disable|mypy:[[:space:]]*ignore|nosec|pragma:[[:space:]]*no[[:space:]]*cover)|//[[:space:]]*(nolint|lint:ignore)|#!?\[(allow|expect)\(|@(file:)?Suppress(Warnings|Lint)?\(|\[SuppressMessage\(|#pragma[[:space:]]+warning[[:space:]]+disable|#nullable[[:space:]]+disable|NOPMD|CHECKSTYLE:OFF|rubocop:(disable|todo)|standard:disable|ktlint-disable|phpstan-ignore|psalm-suppress|phpcs:(ignore|disable)|swiftlint:disable|//[[:space:]]*ignore(_for_file)?:|shellcheck[[:space:]]+disable' | tag ban.suppression

#    ban.empty-catch: the one-line form, a body holding only a comment, the promise form,
#    and the analogs (`except: pass`, `with suppress(`, an error discarded into `_`, an empty
#    `if err != nil {}`, Ruby's inline `rescue nil`, a Rust `.ok();` that drops the Result).
scan  '(^|[^[:alnum:]_])catch[[:space:]]*(\([^)]*\))?[[:space:]]*\{[[:space:]]*(/\*([^*]|\*[^/])*\*/[[:space:]]*)?\}' | tag ban.empty-catch
scan  '\.catch[[:space:]]*\([[:space:]]*(async[[:space:]]+)?(\([^)]*\)|[[:alnum:]_$]+)[[:space:]]*=>[[:space:]]*(\{[[:space:]]*(/\*([^*]|\*[^/])*\*/[[:space:]]*)?\}|undefined|null|void 0)|\.catch[[:space:]]*\([[:space:]]*(async[[:space:]]+)?function[[:space:]]*[[:alnum:]_$]*[[:space:]]*\([^)]*\)[[:space:]]*\{[[:space:]]*\}' | tag ban.empty-catch
scan  '(^|[^[:alnum:]_])except([[:space:]][^:]*)?:[[:space:]]*(pass|\.\.\.)[[:space:]]*(#.*)?$|with[[:space:]]+(contextlib\.)?suppress[[:space:]]*\(|(^|[[:space:]])_[[:space:]]*=[[:space:]]*err([^[:alnum:]_]|$)|err[[:space:]]*!=[[:space:]]*nil[[:space:]]*\{[[:space:]]*\}|rescue([[:space:]]+[A-Z][A-Za-z:]*)?[[:space:]]+nil[[:space:]]*$|\.ok\(\);' | tag ban.empty-catch
#    A catch whose closing brace sits on a later line, with nothing but comments between, is
#    the same empty catch, and so is an `except:` whose next statement is `pass`. grep reads one
#    line at a time, so this is one awk pass. awk on macOS takes no `--`, so a relative path
#    is handed over as `./path`.
paths_for_awk() { while IFS= read -r -d '' p; do case "$p" in /*) printf '%s\0' "$p" ;; *) printf './%s\0' "$p" ;; esac; done < "$SCOUT_PATHS"; }
paths_for_awk | xargs -0 -r awk '
  FNR == 1 { kind = ""; f = FILENAME; sub(/^\.\//, "", f) }
  kind == "brace" && /^[[:space:]]*\}/ { print f ":" line ":" text; kind = ""; next }
  kind == "py" && /^[[:space:]]*(pass|\.\.\.)[[:space:]]*(#.*)?$/ { print f ":" line ":" text; kind = ""; next }
  kind != "" && /^[[:space:]]*$/ { next }
  kind != "" && /^[[:space:]]*(\/\/|\/\*|\*|#)/ { next }
  { kind = "" }
  /(^|[^[:alnum:]_])catch[[:space:]]*(\([^)]*\))?[[:space:]]*\{[[:space:]]*(\/\/.*|\/\*.*\*\/)?[[:space:]]*$/ { kind = "brace"; line = FNR; text = $0 }
  /^[[:space:]]*except([[:space:]][^:]*)?:[[:space:]]*(#.*)?$/ { kind = "py"; line = FNR; text = $0 }
' | tag ban.empty-catch

#    ban.bare-error: with or without `new`, the built-in error classes of the ECMAScript and
#    JVM/.NET/PHP families (a leading `\` is PHP's global namespace), the promise form
#    `reject(new Error(`, a thrown literal, and the Python and Go analogs. Go's `errors.New`
#    at package level is a sentinel and is fine; indented, inside a function, it is a candidate,
#    and a `fmt.Errorf` carrying `%w` is the wrap-with-cause 1.1 asks for, so it is not one.
ERR='Error|TypeError|RangeError|SyntaxError|EvalError|URIError|AggregateError|Exception|RuntimeException|Throwable|IllegalStateException|IllegalArgumentException|SystemException|InvalidOperationException'
scan  '(^|[^[:alnum:]_])throw[[:space:]]+(new[[:space:]]+[^[:alnum:]_[:space:]]?)?('"$ERR"')[[:space:]]*(\(|;|$)' | tag ban.bare-error
scan  '(^|[^[:alnum:]_$.])([[:alnum:]_$]+\.)*reject[[:space:]]*\([[:space:]]*(new[[:space:]]+)?('"$ERR"')[[:space:]]*\(' | tag ban.bare-error
scan  '(^|[^[:alnum:]_])throw[[:space:]]+(["'"'"'`{[]|-?[0-9]|(true|false|null|undefined)([^[:alnum:]_]|$))' | tag ban.bare-error
scan  '(^|[^[:alnum:]_])raise[[:space:]]+(Exception|BaseException|RuntimeError)[[:space:]]*(\(|$)|^[[:space:]]+.*(errors\.New|fmt\.Errorf)[[:space:]]*\(' | grep -v '%w' | tag ban.bare-error

#    ban.non-null: a postfix `!` reads as non-null only in the ECMAScript family, Swift, Kotlin,
#    C# and Dart, so the `!` row runs on those files alone (16.5); Ruby's `save!`, Rust's `vec![`
#    and a shell's `$!` never reach it. `x!` before a member, a call, a bracket, an operator, a
#    closer or the end of the line; `!=`, `!==` and a definite-assignment `name!: T` are excluded
#    because `=` and `:` are not in the class. Swift's `try!` and `as!` are `!` row hits. Then the
#    analogs on every path: Kotlin `!!`, Rust `.unwrap()` / `.expect(`.
in_nonnull '([[:alnum:]_$)]|\])!([-+*/%&|^<>.[);,}`[:space:]]|$)' | tag ban.non-null
scan  '[[:alnum:]_)]!!([^=]|$)|\.(unwrap|expect)[[:space:]]*\(' | tag ban.non-null

#    ban.inline-type, in the five scoped roles only (16.5): a declared interface or type alias,
#    and an object type literal of 2+ members written into a signature. In the literal row one
#    member has to read as a TYPE (a `?:`, a primitive keyword, or a PascalCase name that is not
#    then dotted or called), so a nested object literal (`{ data: { user: u, token: t } }`), a
#    map of UPPER_CASE constants and `status: Status.Active` are not candidates.
TYPE_WORD='string|number|boolean|unknown|any|never|void|bigint|symbol|[A-Z][A-Za-z0-9_]*[a-z][A-Za-z0-9_]*'
TYPED='[[:alnum:]_$](\?:[[:space:]]*[A-Za-z(][^{};,]*|:[[:space:]]*('"$TYPE_WORD"')([^[:alnum:]_.({};,][^{};,]*)?)'
MEMBER='[[:alnum:]_$]\??:[[:space:]]*[A-Za-z(][^{};,]*'
in_scoped '^[[:space:]]*(export[[:space:]]+)?(declare[[:space:]]+)?(interface[[:space:]]+[[:alnum:]_$]+|type[[:space:]]+[[:alnum:]_$]+[[:space:]]*(<[^>]*>)?[[:space:]]*=)' | tag ban.inline-type
in_scoped ':[[:space:]]*\{[^{}]*('"$TYPED"'[[:space:]]*[;,][^{}]*'"$MEMBER"'[^{}]*|'"$MEMBER"'[;,][^{}]*'"$TYPED"'[[:space:]]*([;,][^{}]*)?)\}' | tag ban.inline-type

#    test.focused and test.skipped, in test files only: a focus token, or a skip token with no
#    ticket or owner anywhere after it (`.skip('PROJ-123: flaky')` is owned).
in_tests  '\.only[[:space:]]*[(.]|(^|[^[:alnum:]_.])(fit|fdescribe|ftest|fcontext)[[:space:]]*(\(|["'"'"'])|focus:[[:space:]]*true' | tag test.focused
in_tests  '\.(skip|todo)[[:space:]]*[(.]|(^|[^[:alnum:]_.])(xit|xdescribe|xtest|xcontext)[[:space:]]*(\(|["'"'"'])|@(pytest\.mark\.skip|unittest\.skip|Ignore|Disabled)|(^|[^[:alnum:]_.])(pytest\.skip|t\.Skip|t\.SkipNow|markTestSkipped)[[:space:]]*\(|#\[ignore\]' | grep -vE "$OWNED_SKIP" | tag test.skipped

#    clean.debug-artifact: `debugger` and its analogs on every path; `console.*` in the
#    domain roles only, where the project's logger is the one allowed output.
scan  '(^|[^[:alnum:]_$.])(debugger[[:space:]]*(;|$)|breakpoint\(\)|pdb\.set_trace\(|import[[:space:]]+i?pdb|binding\.pry|byebug|var_dump\(|dd\()' | tag clean.debug-artifact
in_domain '(^|[^[:alnum:]_$.])console\.(log|debug|info|warn|error|trace|dir|table|group|time)[[:space:]]*\(' | tag clean.debug-artifact

#    clean.removed-comment and clean.debt-marker, behind any comment opener the stack uses
#    (`//`, `#`, `/*`, `<!--`, SQL's `--`, a continued `*`). An owned marker is not debt.
scani '(//|#|/\*|<!--|--|^[[:space:]]*\*)[[:space:]]*removed[[:space:]]*[:-]' | tag clean.removed-comment
scan  '(//|#|/\*|<!--|--|^[[:space:]]*\*)[[:space:]]*(TODO|FIXME|HACK|XXX)([^[:alnum:]_.]|$)' | grep -vE "$OWNED_DEBT" | tag clean.debt-marker

#    Secrets. The only critical-severity family, so it runs on every path whatever the
#    stack, and the matched value is REDACTED before it reaches the terminal or the log:
#    stage the file:line and the rule_id, never the credential. A bare ALL_CAPS env NAME on
#    the right-hand side is not a secret.
secret()  { scan  "$1" | sed -E "s#$1#[REDACTED]#g" | tag sec.hardcoded-secret; }
secreti() { scani "$1" | sed -E "s#((=>|[:=])[[:space:]]*[\"'])[^\"']+([\"'])#\1[REDACTED]\3#g" | tag sec.hardcoded-secret; }
#    whole_line: for a row whose value is unquoted, keep only file:line and blank the rest.
whole_line() { sed -E 's#^([^:]*:[0-9]+:).*#\1[REDACTED]#'; }
secret  'AKIA[0-9A-Z]{16}'                                                                    # aws-access-key
secret  '-----BEGIN[ A-Z]*PRIVATE KEY( BLOCK)?-----'                                         # private-key-pem
secret  'gh[opsur]_[A-Za-z0-9]{36}|github_pat_[A-Za-z0-9_]{40,}|glpat-[A-Za-z0-9_-]{20,}'   # github-gitlab-token
secret  'xox[baprs]-[A-Za-z0-9-]{10,}|hooks\.slack\.com/services/T[A-Za-z0-9]+/B[A-Za-z0-9]+/[A-Za-z0-9]+'   # slack-token
secret  'AIza[0-9A-Za-z_-]{35}'                                                              # google-api-key
secret  'sk-[A-Za-z0-9_-]{20,}|[sr]k_(live|test)_[A-Za-z0-9]{16,}|whsec_[A-Za-z0-9]{20,}'   # openai-anthropic-stripe
secret  'npm_[A-Za-z0-9]{36}|SG\.[A-Za-z0-9_-]{22}\.[A-Za-z0-9_-]{43}|hf_[A-Za-z0-9]{30,}' # npm-sendgrid-huggingface
secret  'eyJ[A-Za-z0-9_-]{8,}\.eyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}'                    # jwt
secret  '[a-z][a-z0-9+.-]*://[^/:@[:space:]"'"'"'$]+:[^@/[:space:]"'"'"'$]+@'               # url-embedded-credentials
secret  '["'"'"']Bearer [A-Za-z0-9_.~+/=-]{20,}["'"'"']'                                    # bearer-literal
#    assigned-secret, two shapes. A quoted literal beside a secret-shaped key, in any language
#    (`password = "…"`, `"password": "…"`, `'password' => '…'`): the value carries no spaces,
#    so a sentence is not a secret. An unquoted value where the key starts the line, which is
#    only literal in YAML, properties, ini and env files (`smtp_password: …`, `export API_KEY=…`,
#    `DB_PASSWORD=…`); `$`, `{`, `(` and a dotted reference (`process.env.X`) are not values.
SECRET_KEY='["'"'"']?[A-Za-z0-9_.-]*(api[_-]?key|access[_-]?key|private[_-]?key|client[_-]?secret|secret|passwd|password|passphrase|credentials?|token)[A-Za-z0-9_.-]*["'"'"']?[[:space:]]*'
secreti "$SECRET_KEY"'(=>|[:=])[[:space:]]*["'"'"'][^"'"'"'[:space:]]{12,}["'"'"']'                       # assigned-secret, quoted
scani   '^[[:space:]]*(export[[:space:]]+)?'"$SECRET_KEY"'[:=][[:space:]]*[^"'"'"'[:space:]$({}][^[:space:].(]{11,}[[:space:]]*(#.*)?$' | whole_line | tag sec.hardcoded-secret   # assigned-secret, unquoted config line

#    The names and the file kinds (the code rules, Names and One thing per file; 2.2; 12.0.0).
#    Every row below reads a DECLARATION (a keyword before the name, a file's own path, a
#    signature's parentheses) in the languages whose convention is the law's, so a name a
#    framework fixes is a candidate to weigh at the pointer; Go's symbol case (visibility) and C#'s `I`
#    prefix (its own convention) are left out, and shell, SQL, CSS and config files carry none of
#    these rows. in_langs hands a language subset to awk the way paths_for_awk hands the whole list.
in_camel() { in_paths '*.js' '*.jsx' '*.mjs' '*.cjs' '*.ts' '*.tsx' '*.mts' '*.cts' '*.vue' '*.svelte' '*.kt' '*.kts' '*.swift' '*.dart' '*.java' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_snake() { in_paths '*.py' '*.pyi' '*.rb' '*.rs' '*.ex' '*.exs' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_typed() { in_paths '*.js' '*.jsx' '*.mjs' '*.cjs' '*.ts' '*.tsx' '*.mts' '*.cts' '*.vue' '*.svelte' '*.kt' '*.kts' '*.swift' '*.dart' '*.java' '*.php' '*.py' '*.pyi' '*.rb' '*.rs' '*.cs' '*.scala' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_ecma()  { in_paths '*.js' '*.jsx' '*.mjs' '*.cjs' '*.ts' '*.tsx' '*.mts' '*.cts' | xargs -0 -r grep -nE -e "$1" -- /dev/null; }
in_langs() { in_paths "$@" | while IFS= read -r -d '' p; do case "$p" in /*) printf '%s\0' "$p" ;; *) printf './%s\0' "$p" ;; esac; done; }

#    name.type-case: a class, interface, enum, struct, trait or type alias declared in lowercase
#    (`class user_repo`, `type point = …`); `class extends Foo` is an anonymous class, not a name.
in_typed '(^|[^[:alnum:]_])(class|interface|enum|struct|trait)[[:space:]]+[a-z][[:alnum:]_]*[[:space:]]*(\{|\(|:|<|extends|implements|$)' | tag name.type-case
```

**Reconcile before you trust the result.** Paths handed in must equal paths read. A path
the diff deleted is named as deleted; a binary, an unreadable or an oversized file is named
as unread. Any shortfall is MISSING COVERAGE: say so in the report and re-run with the
gap closed. A scan that quietly covered less than the diff it was handed reports as clean,
and that is precisely how a scoped-path bug survives a whole task.

**Other stacks.** The suppression, empty-catch, bare-error, non-null, debug-artifact and

that happens to hold two utility-looking words. Each costs one `false-positive` disposition with
the reason in the audit, and one look at the guard's pointer (a `law-exception:` when the
technology needs the line as written). A regex that avoided them would need a lexer, which is
the scanner's job (16.7), not the grep floor's.

**When the project has its own scanner or linter for any of these rules**, run it instead
of the grep for the rules it covers and keep the greps for the rest. Reuse before you
rewrite. Its output is staged in the same table, one row per finding.

### The semantic tier (what greps cannot see)

The greps stop where precision needs a parser or real understanding. Those rules are judged by reading: at the loop's Check step over the diff, and by the audit's judgment checks (16.6) over a tree, which own DRY, layering, the parameter and nesting caps and dead code. The lenses below name what to look for, each citing its `rule_id` from the audit rule catalog (16.4) or its row in the clean-code catalog (3.4):

| Lens | rule_ids | What it looks for in the touched files |
|---|---|---|
| One construct per file | `scope.one-construct`, `scope.one-component`, `folder.one-component` | A type, enum, constant, config, schema, or style map declared in an implementation file instead of its dedicated `*.types` / `*.constants` / `*.config` / `*.schema` / `*.styles` file; two components in one file |
| Folder conformance | `folder.placement`, `folder.type-home`, `folder.entity-uniqueness` | A new file placed against the project's documented topology; a duplicate entity/model class name |
| Controller purity | `scope.controller-purity`, `scope.re-export` | A request handler doing more than one service call, or a re-export from a non-canonical source |
| Single responsibility | `style.srp`, `style.naming`, `style.ternary` | A unit that needs "and" to describe it; a name that describes what-not-why; a nested or chained ternary |
| Naming | `style.naming.*` (3.4) | A disinforming name, a noise word, a negative boolean, an encoding, a vocabulary drift, a pun |
| Function shape | `style.function-shape` → `style.function.*` (3.4) | A flag argument, a command that also queries, a mutated input, a hidden side effect, mixed abstraction levels, a type switch repeated across files |
| Error handling | `style.error-handling` → `style.error.*` (3.4) | A log-and-continue catch, a lost cause, a contextless error, exceptions as control flow, a vendor error shape in domain code, a try around an un-awaited promise |
| Object design | `style.object-design` → `style.object.*`, `style.class.*` (3.4) | A train wreck, exposed or shared mutable state, primitive obsession, a stringly-typed set, a God module, deep inheritance, temporal coupling, a working constructor |
| Boundaries | `style.boundary.*` (3.4) | A vendor SDK called from many places, a framework type in a domain signature, environment or clock read inline |
| Async ownership | `style.async` → `style.async.*` (3.4) | A floating promise, state carried across an await, a sleep standing in for a signal, background work with no owner |
| Comments | `style.comment.*` (3.4) | A redundant, journal, banner, misleading or mandated comment |
| Reuse & generalization | `style.reuse`, `style.magic-literal` | A near-duplicate that should have been generalized into one shared parameterized helper; an un-named literal (honor the project's do-not-extract floors) |
| SOLID & YAGNI | `solid.ocp`, `solid.lsp`, `solid.isp`, `solid.dip`, `solid.yagni` | Stable code edited instead of extended; a speculative abstraction or an unused knob |
| Idiom | `style.idiom` | A deprecated API, a hand-rolled version of a built-in, a construct older than the pinned version's idiom where the codebase sets no convention, a feature or API newer than the pin (1.1, Idiom) |
| Leftovers, both directions | `scope.dead-code`, `style.structure.unused-import`, `clean.unused-dep`, `clean.unref-file`, `clean.dead-flag`, `clean.orphan-env`, `clean.commented-code`, `clean.removed-comment` | A symbol the diff added with no caller, or one it orphaned by removing the last caller, import or reference; a dead symbol that was already in a touched file (a side find, never removed here: 1.9); an unused import, dependency, flag or env var; a commented-out block or a `// removed:` marker |
| Test coverage | `test.untested`, `test.edge-cases` | A service method, guard, or branch shipped by this task with no covering test (`test.untested`). `test.edge-cases` is judged against the test-scenario catalog (3.3) — boundary values, invalid/malformed input, empty/duplicate/oversized collections, concurrency/idempotency, authorization denial, error propagation, lifecycle transitions, external non-determinism — never a vague "did you add edge cases" call, and only the domains the touched code owes (3.3, What each kind of code owes), not all eight reflexively |
| Test hygiene | `test.hygiene` → `style.test.*` (3.4) | A test with no assertion, several concepts in one test, an order-dependent or non-deterministic test, a mocked subject, an expectation pasted from the code's own output |

Carve-outs are honored before anything is reported: test files, generated code, migrations, and the project's own documented exceptions (16.5). Flagging a documented exception teaches the user to ignore the scan.

### STAGING (the audit's table)

The codebase audit stages findings in exactly this table, in chat, and 16.8 carries it into the report. The coverage line (paths handed in / paths read) goes above the rows on every run, including a run with no rows:

```markdown
### Law-scout (<run-point-id>, <YYYY-MM-DD>)

| Finding | rule_id | file:line | Evidence | Proposed fix | Status |
|---|---|---|---|---|---|
| Empty catch swallows the parse error | ban.empty-catch | src/import/parse.ts:41 | `catch (e) {}` | log and rethrow as `ImportParseError` | staged |
| Inline `type` in a scoped module | ban.inline-type | src/users/users.service.ts:12 | `type CreateArgs = { … }`, 4 props | move to `users.types.ts` | fixed |
| Focused test left on | test.focused | src/users/tests/users.service.test.ts:88 | `it.only(` | drop `.only` | fixed |
| Bare Error in a UI asset | ban.bare-error | web/src/boot.tsx:9 | throw is in presentation, not domain code | none | false-positive: not domain code |
```

- **`<run-point-id>`** is the tree the run covered (`src/`, or `.` for the whole project), so two tables are told apart by it.
- **rule_id** is the first word of the scout's line, copied as printed.
- **Status** is one of `staged` / `fixed` / `false-positive: <one-line reason>`.
- **Into the audit report** (16.8): Finding, file:line and Evidence carry over; Severity maps from the catalog (`critical` → Critical, `high` → Critical, `medium` → Important, `low` → Minor), and the judgment checks (16.6) may move it one level in context with the reason stated. `staged` rows wait for the maintainer's decision (16.3).

### TRIAGE

- **Every finding gets exactly one disposition**, `staged`, `fixed`, or `false-positive`. A finding that vanishes without a row is a protocol violation, not a judgment call.
- **Dismissing needs a one-line reason** tied to a documented carve-out or the run context (test fixture, generated file, project exception).
- **`sec.hardcoded-secret` can never be dismissed on your own.** It is the only catalog-critical mechanical rule. A candidate is `fixed` (the secret moved out of source and rotated) or `staged` for the maintainer, who alone may mark it a false positive, with a counter-citation; in the loop, the guard's pointer is answered by fixing the line, and a real secret is reported at once (1.9). Its rows arrive redacted; never paste the value back into the table to "show" it.
- **`note.law-exception` is a listing, not a finding.** Each line it prints is a technical exception stated at the guard's pointer; the audit shows them in their own table so every exception in the codebase is seen, and asks about one only when the technology it names no longer needs it.
- **`test.focused` is never `staged`.** A `.only` left on is `fixed` on sight, whatever files the scope line named, because a suite that runs one test is a suite that ran nothing.
- **The three syntactic rules need the one-step check before staging.** `ban.bare-error`: is the throw in domain code? `ban.inline-type`: does the declaration have 2+ properties? `clean.debug-artifact`'s `console.*` row: is the file domain code, or the logger module itself? Record the answer in Evidence, not the fact that you checked.
- **A `@ts-expect-error` in a test file is the one allowed suppression** (1.1), and only with a comment saying WHY on the same or the previous line. With the comment it is `false-positive: 1.1 sole exception`; without it, it is `staged` like any other suppression.
- **Fix-in-task is allowed** only inside the scope line's files, and the fix is part of the diff the Check step reads. A fix outside those files is a scope change: the scope ratchet (the law) restates the scope in at most 3 lines, on the task line too, and goes on. In the audit, every `staged` row waits for the maintainer's approval (16.3).
- **Pre-existing findings in touched files are reported, never fixed here.** A cap break or empty catch that the task did not introduce, but which lives in a file the task edited, is a `present at base` row: it goes on the side-finds list with its `file:line` (1.9). Untouched files stay out of scope.
