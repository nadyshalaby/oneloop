# 4.4 [route] The sub-commands, the intake and the agent modes

The route table in the workflow skill (`skills/workflow/SKILL.md`) names seven routes. Each one has a sub-command of its own, the
bare invocation runs a guided intake, and every route runs its phases as agents (1.8) unless
the user switched that off. This file is the whole of that contract. The workflow skill's "Invocation"
points here, and the always-on part of the agent modes is in 1.8, so that none of it depends
on having reached this file.

## The sub-commands

| Sub-command | Route | Section | What follows it |
|---|---|---|---|
| `/engineering-rules:quick` | Quick mode | 4.2 | the request |
| `/engineering-rules:full` | Full mode | 4.3 | the request |
| `/engineering-rules:brainstorm` | Brainstorm (shaping) | 16.1 | the idea |
| `/engineering-rules:audit` | Codebase audit | 16.3 | a project root or directory; nothing means the current project |
| `/engineering-rules:triage` | Review triage | 16.2 | the pasted findings |
| `/engineering-rules:design-spec` | Design system | 15.19 | the mode or a direction; nothing means detect it |
| `/engineering-rules:release-notes` | Release notes (the update log) | 16.13 | nothing |

Each is a personal skill this setup installs as `~/.claude/skills/engineering-rules:<route>`, from `skills/<route>/SKILL.md`, and only the user can invoke it:
the model cannot call one, so a route reached through a sub-command was picked by the user
and nobody else. Its body does three things and nothing more. It loads this skill, through
the Skill tool with `engineering-rules:workflow`, so the always-on law binds. It
reads the request that follows. Then it hands over to the route's own section. A sub-command picks the row and skips the classification in 4.1. It waives nothing:
not a phase, not a check, not a gate, not the question contract. Quick mode named by
`/engineering-rules:quick` is quick mode named by the user, which is the one way quick mode
ever starts (4.2).


**The request.** Everything after the sub-command. When that is empty, the request is the
most recent ask in this conversation, in the user's own words. When there is none either,
ask for it through the wizard tool, one question, and ask nothing else: the mode stays as the
conversation has it, agents on unless switched off, because a bare sub-command is somebody
who already said which route they want. `audit`, `design-system` and `release-notes` are
complete with nothing after them.

**Typed into the main skill.** `/engineering-rules:workflow <request>` carries no
route token any more. The request classifies under 4.1 exactly as prose does: a route the
user names in their words still picks itself, and a first word that used to be a token
(`full`, `shape`) is their word too.

## The intake, when the skill is invoked bare

`/engineering-rules:workflow` with nothing after it, from the chat box, is a user who
wants to be walked through the options. Three facts have to be settled before anything
starts: the route, the mode, and the request. Settle them through the wizard tool, in
as few calls as the answers allow, and never with a question the last answer did not make
necessary. The wizard holds four options per question, so the seven routes are reached in two
steps, never listed in one.

1. **What are you here for?** Four options, the first recommended.
   - *Build, fix or change something* → quick or full mode, step 2a.
   - *Think an idea through before building it* → shaping.
   - *Understand or judge code that is already there* → the audit.
   - *Something else* → triage, the design system or the release notes, step 2c.
2. **Which route**, only where step 1 left more than one.
   - **2a**: *Full mode: a written plan, a spec review, a durable work-doc*
     (recommended) / *Quick mode: every check, no written plan*.
   - **2c**: *Respond to a batch of review findings* / *Author or refresh the design spec* /
     *Print the release notes of the task in flight*.
3. **How it runs**, in the same call as step 2 where there is one: *Agents: each phase on the
   agent and model 1.8's map names* (recommended, the default) / *Agentless: every phase in
   this chat*. Not asked for the release notes, and not asked when the user's own words
   already settled it this conversation: that answer stands.
4. **The request**, in the words the route needs: the task, the idea, the findings, the design
   mode. The audit and the release notes need none. Offer
   *Continue what this conversation was last discussing* when there is such a thing, else
   *Start from the repository: read its rules, README and layout, then ask me again*; and
   *Not sure yet, shape it with me*, which is shaping. The wizard's own free-text choice is
   where they type it. A request that reads as a different route than the one chosen is put
   back as one more question, never silently re-routed.

The intake ends the moment all three facts are known, and the next line is the route and mode
statement of 1.7, step 2. Nothing is classified, no ledger opens and no file is read for the
task before then. The intake never fires when this skill loaded automatically because a task
began, when the message carries a request in any form, or when a sub-command loaded it: a
menu in front of somebody who already said what they want is ceremony (4.1).

## The two modes

**Agents on, the default.** Every phase runs as the agent 1.8's map names, on the model that
row names: a fork for the readers that need this conversation, an `Explore` reader and a
`sonnet` builder and mechanic for the search, the code and the commands, an `opus` planner,
spec reviewer and reviewer for the plan, the audit of the plan and the review of the diff.
The session keeps the anchor, the ledger, every question, the ship gate, the commits and every
claim. The recorded line is `Agents: on, the default; every phase runs on the map in 1.8.`,
after one probe of the runtime, or `Agents: unavailable, every phase runs in this session.`
when the probe finds no agent tool (1.8, 5.1).

**Agentless, the opt-out.** Every phase's work runs in this session and nothing is sent to
the agent tool for the whole task. It is the collapse rule of 1.8, *where the runtime offers
no agent tool, every shape runs here*, taken on purpose.

**What switches agentless on.** Any one of these, and nothing else:

- the user saying so in their own words in the message that starts the task (*"no
  subagents"*, *"keep it in this chat"*, *"don't fan out"*), or the intake's question;
- a standing line to that effect in the user-global or project `CLAUDE.md`, which is the
  user's words for every task until they change it.

Agentless is never chosen from the size of the task, the model, the runtime's load or a send
that would be quick to brief. Those are reasons to offer it in one line, never to take it.

**What it changes.** The recorded line reads `Agents: off, by user choice; every phase runs
in this session.` (1.8, 5.1), and every row of the map in 1.8 is the same work done here, in
the row's order, with the output the send would have returned:

- Phase 1 composes the question batch here, after reading 6.2, 6.4, 6.5, the matched bank,
  6.12 and 6.15 from disk;
- Phase 2 drafts the plan here, and Phase 3b the hypothesis chain;
- the scouts (9.4, 9.5, and 15.29 on UI-bearing work) are read from disk and run here at
  every stage end and at Phase 5 start, staging tables and all;
- the spec review of Phase 2.5 (8.2) and the five checks of Phase 5 (12.3 to 12.7) run here,
  one lens at a time, each check read from disk as it opens and closed before the next opens,
  over a fresh `git diff` and never over memory;
- every stage is built here inside its allowlist, and every count, grep and planted-instance
  proof (1.5) runs here with its output pasted.

Each affected ledger item records `agent skipped: agents off, by user choice`, which 1.8 and
5.1 accept as the recorded agent line. Nothing else moves: not a check, not a scout, not a
gate, not the evidence rules, not the wizard tool, not the caps and bans.

**What agentless costs, said once at task start, in one line.** The fresh eyes of the Phase 5
review and the spec review are gone: the context that wrote the diff is the one reading it.
Every reference an agent would have read in a throwaway context is read into this one, so the
session thinks in what is left. And the split of models is gone, so the session's own model
does the typing as well as the judging. *"Agentless: the review loses its fresh eyes, the
reading lands in this context, and one model does every job."*, or words to that effect, and
then the task runs.

**Switching back.** The user says so in their own words, at any boundary. The session probes the runtime once as 1.8 says, prints
`Agents: on, by user choice.` on its own line, and the sends resume from the next run point;
nothing already done is re-done, and the switch holds for the tasks that follow. Switching to
agentless mid-task works the same way, with the cost line printed again.

## Anti-rationalizations

| Thought | Reality |
|---|---|
| "Agentless, so the scouts and the review can be lighter." | Agentless moves the work here; it removes nothing. Every scout, every check, every count runs in this session, in the same order, with the same tables. |
| "The task is small, I'll keep it in this chat." | The user switches agents off. Offer it in one line; do not take it. |
| "The session is on opus, so the builder is too." | The builder row says `sonnet` and the send names it. A send with no model takes the runtime's default, which is not the map (1.8). |
| "The user typed a sub-command, so the clarify round is theirs to skip." | A sub-command picks the route. Phase 1 runs in full on every route that has one. |
| "Bare invocation, I'll guess the route from the last message." | Three facts, through the wizard tool, then start. The last message is an option offered, never a guess taken. |
| "The intake needs seven options and the wizard holds four." | Two steps: what they are here for, then which route in that bucket. |
| "A fork is not really an agent, so agentless still allows one." | A fork is a send. Agentless sends nothing; the file is read here. |
| "The switch was two tasks ago, surely it lapsed." | It holds for the conversation until it is switched back or the user's words change it. Record it on every task's agent line. |
