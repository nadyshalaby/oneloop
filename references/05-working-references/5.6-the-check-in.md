# 5.6 [reference] The check-in, every ten minutes and at every boundary

**A task that runs for an hour with nothing visible is a task nobody can steer.** The phase
ledger (5.1) makes the phases visible at their boundaries. This makes the work visible
between them, on the clock, so the user can correct course before an hour of it is wrong.
Read this at task start with 5.1, and follow it for the whole task in every mode.

## When it fires

- **Every ten minutes of wall clock**, from task start or from the last check-in.
- **At every phase boundary and every stage end**, where it rides along with the reflection
  5.1 already asks for.
- **Whenever the user asks for one**, in whatever words.

A check-in never ends the work. It is a checkpoint inside the work, and the next thing after
it is the next step of the task, not a question and not a summary.

## What it is, in this order

1. **The work-doc first**, in full mode, before anything else is written. Bring the in-flight
   doc (`docs/work/<slug>.md`, not `done/`) up to date: tick every item that is finished and
   proven, in the phase ledger, the Sprint Backlog and the Acceptance Criteria, each with its
   one-line reflection; add the Daily Updates line for what landed since the last check-in;
   set the frontmatter `status`; and republish the page where the doc has one (7.3). A tick
   that is true and unwritten is the thing this step exists to catch.
2. **The brief, three short lines**, in plain words, with no task ids, numbers or codes
   (`SKILL.md` 1.4, 5.3):

   ```
   Doing: what is in progress right now
   Done:  what finished since the last brief
   Todo:  what is left
   ```

   When nothing changed since the last brief, one line instead: `No change, still on <the
   thing>.`
3. **The drift check** (1.9), one line: the goal, and whether the work since the last
   check-in served it. Work that did not is named, stopped and moved into the follow-ups, in
   that order, and the next step goes back to the goal.
4. **Then keep working.**

## All the time, not only at a check-in

- **Tick the moment it is done and proven.** Never save ticks for the next check-in; a
  deferred write is no tick at all (`SKILL.md` 1.4).
- **Stay on the goal.** Side findings go to the follow-ups and are chased only when they
  block the goal (1.9).
- **Say it in one line when you catch yourself drifting or wrong**, fix it there, and carry
  on. A correction costs a line; a hidden correction costs the review.

## When work keeps running after your turn ends

Agents in flight, a long build, a deploy, a watcher, a remote job: before you stop, make sure
the check-in keeps firing without you. On Claude Code that is the `loop` skill at a ten-minute
interval; on another runtime it is whatever that runtime schedules with. When a check-in fires
and nothing at all is in flight, say so in one line and stop the schedule; it comes back when
work starts again.
